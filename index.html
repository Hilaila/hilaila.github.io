Architecture de confiance

Principe : le navigateur présente et collecte ; Pi authentifie ; le backend vérifie l'accessToken, applique les règles métier, décide le KYC, recalcule le burn, contrôle les doublons et enregistre la demande. Les secrets serveur et les clés Supabase ne sont jamais placés dans ce fichier.

La création d'un actif réellement on-chain, le burn effectif et les mouvements de Pi nécessitent les mécanismes serveur appropriés. Cette interface ne simule pas ces opérations : elle appelle les endpoints configurés et affiche leur résultat.
